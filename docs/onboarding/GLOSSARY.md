# Glossary (as-found baseline)

> Domain terms, internal jargon, and codebase-specific naming conventions
> encountered while mapping OpenEMR **as we found it** (baseline commit
> `859d6d3`, 2026-07-06). Definitions are grounded in code/tests; where intent
> was unclear it is marked *(uncertain)* and carried into
> [`OPEN_QUESTIONS.md`](OPEN_QUESTIONS.md). Companion to
> [`CURRENT_ARCHITECTURE.md`](CURRENT_ARCHITECTURE.md).

## Domain terms (healthcare / EHR)

| Term | Meaning in this codebase |
|---|---|
| **EHR** | Electronic Health Records — the clinical side of the app. |
| **Practice management** | The scheduling/billing/administrative side. |
| **pid** | Patient ID — the legacy integer primary key for a patient (`patient_data.pid`). Still returned by the API alongside `uuid`. |
| **uuid** | The modern UUID identity for a resource, added on top of legacy integer PKs. Patients (and many resources) carry **both** a `pid`/integer id and a `uuid`. |
| **puuid** | "Patient UUID" — the UUID form of a patient identifier, used in API routes (`GET /api/patient/:puuid`). Same pattern: `fuuid` (facility), `euuid` (encounter), etc. |
| **Encounter** | A single clinical visit/interaction for a patient. Central clinical unit; forms attach to encounters. |
| **Facility** | A physical clinic/location. Login and many operations can be facility-scoped (`login_into_facility`, `pc_facility` cookie). |
| **Form** | A clinical data-entry module attached to an encounter (`interface/forms/**`, `src/Forms`). OpenEMR forms are pluggable. |
| **Layout / layout field** | Configurable form-field definitions driven by data (`library/options.inc.php`), rendered per `data_type`. See `FieldRenderingSnapshotTest`. |
| **List / list_options** | Generic configurable dropdown/enumeration system (`list_options` table, `list_id`). Used pervasively (e.g. the `apps` list on the login screen). |
| **ACL / phpGACL** | Access Control List authorization, historically via the phpGACL library (`gacl/`, `src/Gacl`, `AclMain`, `AclExtended`). Governs what a user may do. |
| **FHIR** | Fast Healthcare Interoperability Resources — the HL7 REST standard. `src/FHIR`, `src/Services/FHIR`, routes in `_rest_routes_fhir_r4_us_core_3_1_0.inc.php`. |
| **US Core** | The US-specific FHIR profile set OpenEMR certifies against (R4, US Core 3.1.0 per the route filename). |
| **C-CDA / CCR / CCD** | Consolidated Clinical Document Architecture / Continuity of Care Record — XML clinical document exchange formats. Generated by the Node `ccdaservice`/`ccr` services. |
| **ECQM / CQM / QDM** | Electronic Clinical Quality Measures / Clinical Quality Measures / Quality Data Model — regulatory quality reporting. `src/Cqm`, `tests/Tests/ECQM`, `MeasureService`. |
| **QRDA** | Quality Reporting Document Architecture — the export format for quality measures (`src/Services/Qrda`). |
| **EHI export** | Electronic Health Information export — bulk patient-data export for regulatory compliance (`Documentation/EHI_Export`). |
| **Inferno / G10** | ONC's FHIR certification test kit ("Inferno") and the "(g)(10) Standardized API" certification criterion. `tests/Tests/Certification` targets these. |
| **SMART (on FHIR)** | The SMART App Launch authorization framework layered on OAuth2/OpenID Connect. `src/RestControllers/SMART`, `.well-known/smart-configuration`. |
| **Direct / Direct messaging** | The "Direct" secure clinical messaging standard (EMR Direct integration in `library/direct_message_check.inc.php`). |
| **MedEx** | A patient-reminder / recall subsystem (`library/MedEx`) — SMS/voice/email reminders. |
| **Provenance** | A FHIR resource tracking the origin/authorship of data; has its own API test. |

## Internal / codebase jargon

| Term | Meaning |
|---|---|
| **Golden path** | (Our term, used in the onboarding docs) the primary happy-path flow through a subsystem — login, an API request, a background job. |
| **The two-bootstrap seam** | (Our term) the fact that legacy pages init via `interface/globals.php` while the API inits via `bootstrap.php` + `SiteSetupListener`. See architecture doc §5. |
| **`$ignoreAuth`** | Ambient global variable a page sets **before** including `globals.php` to opt out of authentication enforcement. `$ignoreAuth_onsite_portal` is the patient-portal variant. |
| **globals / `$GLOBALS` / OEGlobalsBag** | The global configuration/settings bag. Legacy code reads `$GLOBALS['setting']`; new code uses `OEGlobalsBag` (extends Symfony `ParameterBag`, typed getters like `getBoolean`/`getString`/`getInt`). Both are populated by `globals.php`. Distinct from the `globals` **DB table**, which persists settings. |
| **`sqlconf.php`** | Per-site database connection config at `sites/<site_id>/sqlconf.php`. The real DB config for the legacy app (not `.env`). |
| **site / site_id / multi-site** | OpenEMR is multi-tenant by "site": each site has its own `sites/<id>/` dir and DB config, selected via `?site=` or hostname. `default` is the standard single-tenant site. |
| **QueryUtils** | The sanctioned data-access helper (`src/Common/Database/QueryUtils`) — `fetchRecords`, `querySingleRow`, `sqlStatementThrowException`, etc. Preferred over raw `sqlStatement()`. |
| **BaseService** | Base class all modern services extend (`src/Services/BaseService`); constructor takes a `TABLE_NAME`. The standard service-layer pattern. |
| **ProcessingResult** | The standard return envelope from service methods — carries `data`, `validationErrors`, `internalErrors`. Serialized by `RestControllerHelper` into the API's JSON envelope. |
| **HttpRestRequest** | OpenEMR's request object (`src/Common/Http`), extends Symfony `HttpFoundation\Request`; adds `isFhirRequest()`, `isPortalRequest()`, etc. |
| **RestConfig / ROUTE_MAP** | `RestConfig::$ROUTE_MAP` / `$FHIR_ROUTE_MAP` / `$PORTAL_ROUTE_MAP` — associative arrays of `"VERB /path/:param" => closure` loaded from `_rest_routes*.inc.php`. |
| **RouteFinder** | `StandardRouteFinder` / `FhirRouteFinder` / `PortalRouteFinder` — pick the matching route for a request. |
| **request_authorization_check** | `RestConfig::request_authorization_check($request, "section", "sub")` — the per-route authorization gate, called inside route closures with bare string scopes. |
| **Ajax piggyback** | The mechanism where background services are checked/run on the back of AJAX polls from the logged-in UI (see `execute_background_services.php` header and `OPENEMR__NO_BACKGROUND_TASKS`). |
| **background_services (table)** | DB table defining background jobs as `(name, function, require_once path, execute_interval, sort_order, lock_expires_at, next_run, running, active)`. Driven dynamically by `BackgroundServiceRunner`. |
| **lease / lock_expires_at / GET_LOCK** | Background-service concurrency control: a per-service DB "lease" (`lock_expires_at`) plus a DB-wide MySQL advisory `GET_LOCK` orchestrator lock. Expired leases are stolen from crashed workers. |
| **EventAuditLogger** | The audit-trail writer (`src/Common/Logging`) — records logins, logouts, auth failures, etc. to the audit log. Distinct from `SystemLogger` (PSR-3 app logging). |
| **AuthHash / AuthUtils** | `AuthUtils` = the credential-verification orchestrator (login/api/portal/other modes); `AuthHash` = the password hashing/verification primitive. |
| **preventTimingAttack / dummy hash** | Defensive login code: a stored `hidden_auth_dummy_hash` global used to make nonexistent-user auth take the same time as real verification. |
| **TwigContainer** | OpenEMR's Twig wrapper (`src/Common/Twig`) used to render modern templates, often via a `TemplatePageEvent` dispatched through the event system. |
| **Isolated tests** | The DB-less PHPUnit suite (`phpunit-isolated.xml`, `#[Group('isolated')]`) — fast, pure-logic + Twig compile/render. The largest test suite (~227 files). |
| **Fixture / FixtureManager** | Test data helpers (`tests/Tests/Fixtures`) that seed and remove records for DB-backed and API tests. |
| **Snapshot / golden fixtures** | Recorded expected-output files (Twig render + layout-field HTML) regenerated with `composer update-twig-fixtures` / `update-layout-field-fixtures`. |
| **openemr-cmd** | The project's dev CLI wrapper (per `CLAUDE.md`) around docker/test/quality commands, including a git-worktree workflow. Not part of the app runtime. |
| **flex / flex-core** | Docker build variants (`docker/flex`, referenced by CI workflows) — packaging targets, not app subsystems. |

## Naming conventions observed

- **`OpenEMR\` PSR-4 namespace** maps to `/src`. Legacy classmap classes live in
  `library/classes`. Procedural helpers are `*.inc.php` in `/library`.
- **`*Service.php`** = service-layer class; **`*RestController.php`** = REST 
  controller; **`*RouteFinder`**, **`*Listener`/`*Subscriber`** = dispatch/event
  wiring.
- **`*.inc.php`** = a legacy include (procedural, often relies on ambient globals
  like `$ignoreAuth`, `$sessionAllowWrite`). Route tables are `_rest_routes*.inc.php`.
- **Route params** use a `:name` placeholder and a `<thing>uuid` convention
  (`:puuid`, `:fuuid`, `:euuid`).
- **E2e test ordering by filename prefix:** `Aa`, `Bb`, `Cc`, … `Jj`, `Kk`
  prefixes on `tests/Tests/E2e/*Test.php` force alphabetical execution order so
  a stateful chain runs in sequence (login → create staff → create patient →
  …). Combined with `#[Depends(...)]`. *(This is a convention to be aware of,
  not necessarily one to emulate — see the testing review.)*
- **`declare(strict_types=1)`** on every new PHP file; native type declarations
  expected. Legacy files often lack both.
- **Commit messages** follow Conventional Commits (`type(scope): desc`);
  AI-assisted commits add an `Assisted-by:` trailer (per `CLAUDE.md`).

## Clinical Co-Pilot & compliance terms

Terms used by the co-pilot product docs (`PRD.md`, `USERS.md`, `ARCHITECTURE.md`).
Our coined terms are marked *(our term)*.

| Term | Meaning |
|---|---|
| **PHI** | Protected Health Information — individually identifiable health data governed by HIPAA. In the co-pilot, anything sent to the model that could identify a patient. |
| **BAA** | Business Associate Agreement — the contract a vendor (e.g. an LLM provider) must sign before it may process PHI on the clinic's behalf. |
| **Zero data retention** | An LLM-provider setting/contract term where prompts and outputs are not stored or used for training. |
| **Minimum necessary** | HIPAA rule: disclose only the PHI a task actually requires — here, curate the prompt to the fewest fields needed. |
| **CDS (clinical decision support)** | Software that informs (not replaces) a clinician's decision. "Reviewable-basis" CDS — the clinician can inspect the basis for the output — is more likely to fall outside FDA medical-device regulation. |
| **Provenance** | Every surfaced claim links back to its exact source record (`{patient, resource, timestamp}`). The point-of-use defense against wrong-but-shown facts. (Distinct from the FHIR Provenance *resource* above.) |
| **Data-trust layer** | *(our term)* The step that resolves identity, drops inactive rows, dedupes, and normalizes EHR data **before** the agent uses it — the defense against garbage-in. |
| **Synthesis (one-pass)** | *(our term)* Reconciling meds, labs, and allergies together in a single step so cross-source interactions aren't missed; contrasted with isolated per-source summaries. |
| **Must-not-miss set** | *(our term)* The items that must appear in a snapshot for a given patient/visit (a critical result, a dangerous interaction, a real care gap, an unclosed thread). |
| **Critical subset (deterministic)** | *(our term)* The highest-stakes must-not-miss items — panic labs, drug–drug contraindications, drug–allergy conflicts, open follow-ups — surfaced by **code rules, not model judgment**; target zero misses. |
| **Golden-chart set** | *(our term)* Curated (chart-state, visit) → expected-output cases, clinician-adjudicated, used to gate clinical accuracy; grows from production near-misses. |
| **Accuracy gate** | *(our term)* The offline check that **fails a build** if the pipeline misses a critical-subset item or drops below the recall/precision/accuracy floors. |
| **Omission / commission** | *(our term)* The two ways content can be wrong: **omission** = a must-not-miss item never surfaced (invisible; the safety killer); **commission** = a wrong fact in what *is* shown (catchable via provenance). |
